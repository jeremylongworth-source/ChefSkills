# v0.1.0-alpha Evidence Decision

Date: 2026-09-03

## Decision

`v0.1.0-alpha` can ship with the current medium-confidence simulated before/after evaluation evidence.

This is acceptable for a public alpha because the release is framed as a reviewable culinary skill framework, not a benchmark claim, certification, production compliance tool, or proof that live model behavior will match the simulated outputs.

## Rationale

- The current scorecard summary covers 9 reports and 38 evaluated fixtures with 0 blockers.
- The ChefSkills-enabled average is 4.8059 against a baseline average of 3.7599, with a 1.0461 aggregate delta.
- The strongest gains are in culinary reasoning, sensory reasoning, and ingredient understanding, which are the core claims of the framework.
- The weakest current criterion is communication, but it is still above the public-alpha threshold and is not a safety blocker.
- README, evaluation docs, report docs, scorecard docs, and release notes all identify the before/after outputs as medium-confidence local reviewer simulations.
- Publication and repository-settings reviews found no current public-alpha blockers in tracked files, history, collaboration workflow, or maintainable repository settings.

## Release Conditions

This decision remains valid only while these conditions hold:

- Simulated evidence remains clearly labeled in public-facing docs.
- `v0.1.0-alpha` release notes do not claim live benchmark results.
- No new scorecard blockers are introduced before the tag.
- Local validation and GitHub Actions validation pass on the release commit.
- Public visibility is followed by branch protection or ruleset setup for `main`.
- Public visibility is followed by confirmation that issue forms and the security policy page render correctly.

## Residual Risk

Medium-confidence simulated evidence is useful for regression tracking and roadmap decisions, but it does not prove that a live model will reproduce the same behavior under different prompts, model versions, context limits, tool availability, or user constraints.

The public-alpha mitigation is transparency: document the evidence class, keep claims narrow, and make a reproducible live-output harness an explicit post-alpha improvement.

## Post-Alpha Follow-Up

Add a live-output evaluation harness that records:

- fixture id
- route and skillset context
- prompt or prompt template
- model and context notes
- baseline output path
- skill-enabled output path
- scorecard result
- reviewer decision
- rerun notes

The live-output harness should become the preferred evidence source before a beta or broader public launch.
