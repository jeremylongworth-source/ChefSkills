# Open Source Roadmap

## Goal

ChefSkills should become a public open source repository when the framework is safe, reviewable, validated, and maintainable enough for outside users and contributors.

This is a public-alpha readiness path, not a claim that the culinary guidance is regulatory, medical, or professional advice.

## Current State

- Repository visibility: private.
- Current readiness status: `ready_for_public_alpha_readiness_work`.
- Current validation: `.\scripts\validate-all.ps1` passes locally and through GitHub Actions on pushes and pull requests.
- Current scorecard evidence: 9 reports, 38 evaluated fixtures, 0 blockers, baseline average 3.7599, ChefSkills-enabled average 4.8059, delta 1.0461.
- Current confidence caveat: all registered reports are medium confidence because the before/after outputs are locally simulated.

## Pre-Public Workflow

### 2. Improve Evaluation Credibility

The project can go public as an alpha with simulated reports, but the README and reports must say that clearly. A stronger public release should add a reproducible live-output harness for baseline and skill-enabled comparisons.

Status: started. README, evaluation docs, scorecard docs, report docs, and draft release notes now label the current reports as medium-confidence local reviewer simulations. A live-output harness remains future work unless release scope changes.

Acceptance criteria:

Given public readers reviewing the evaluation reports, when they inspect the evidence, then they should be able to tell whether outputs are simulated, manually scored, or generated by a repeatable harness.
Evidence: `evaluation/README.md`, report files, and scorecard metadata.

Given a future live-output harness, when the same fixture is run twice, then the captured route, prompt, model/context notes, output path, scorecard, and reviewer decision should be reproducible enough for review.
Evidence: script output and generated run artifacts.

### 3. Add Public Repository Operations

- GitHub Actions workflow for validation
- issue templates for routing bugs, skill proposals, food-safety concerns, and evaluation fixtures

Given a new public issue, when a contributor chooses a template, then the template should collect scenario, expected route, safety relevance, source evidence, and affected files where appropriate.

### 4. Tighten Public Documentation

### 5. Run Publication Audits

Run a final release-readiness audit before making the repository public:

- secret and private-data scan
- prompt-injection review
- data-exfiltration review
- script-permission review
- supply-chain review

Status: complete for the current tracked tree and history. No publication blockers were found. Remaining follow-ups are GitHub branch/ruleset settings, security-policy link confirmation after public visibility, and the release decision about simulated evaluation evidence.

### 6. Publish `v0.1.0-alpha`

Release only after the readiness gates above pass.

Launch steps:

1. Freeze scope.
2. Regenerate summaries.
3. Run validation and audits.
4. Update changelog and release notes.
5. Tag `v0.1.0-alpha`.
6. Change GitHub repository visibility from private to public.
7. Review the public community profile and repository settings.

Acceptance criteria:

Given the repository is public, when an outside reader visits it, then README, license, contributing, code of conduct, security policy, templates, validation workflow, and alpha release notes should be visible and internally consistent.
Evidence: GitHub repository community profile and release page.

## Future Expansion Tracks

These tracks were captured from the ChefSkills ChatGPT project notes. They should be visible in the roadmap now, but they should not block the public alpha unless the release scope explicitly changes.

### Michelin / Fine-Dining Intelligence

Intent:

- use public Michelin Guide concepts as one lens for fine-dining analysis
- help users refine dishes, menus, technique, consistency, identity, ingredient quality, and competitive positioning
- support gap analysis between a current dish/menu and a target fine-dining level
- support future competition or fine-dining preparation workflows

Source anchors:

- Michelin Guide inspectors list five public restaurant-rating criteria: quality of products, mastery of flavour and cooking techniques, chef personality in the dining experience, harmony of flavours, and consistency between inspectors' visits.
- Source checked 2026-09-03: https://guide.michelin.com/th/en/michelin-guide-inspectors

Guardrails:

- Do not claim to predict, guarantee, simulate, or certify Michelin stars.
- Do not imply any affiliation with or endorsement by Michelin.
- Treat Michelin as a public fine-dining evaluation lens, not a replacement for critic, inspector, or market judgment.
- Separate food quality, service model, business model, location, and inspection eligibility.

Candidate decomposition:

- `fine-dining-evaluation`: evaluate refinement, identity, consistency, and technical execution.
- `menu-competition-analysis`: compare menus, pricing, formats, and positioning.
- `dish-refinement`: improve plate concept, technique, ingredient hierarchy, and sensory arc.
- `restaurant-readiness`: review consistency systems, service fit, sourcing, and operations constraints.

Acceptance criteria:

Given a dish-refinement request, when the fine-dining track is implemented, then the answer should map current dish state to target refinement using observable criteria, not vague prestige language.
Evidence: fixture scorecard.

Given a Michelin-related request, when the answer is generated, then it should include non-affiliation and non-guarantee boundaries where star prediction or certification could be implied.
Evidence: scenario failure modes and report review.

### Canadian Commercial Food Safety

Intent:

- add Canada-specific commercial food-safety and safe-food-handling guidance
- cover sanitation, cross-contamination prevention, allergens, cooling, reheating, holding, storage, traceability, recalls, and preventive controls
- account for federal, provincial, territorial, regional, and municipal boundaries instead of treating Canada as one uniform food-service jurisdiction

Source anchors:

- CFIA states that Health Canada sets food-safety standards while CFIA enforces those standards, and that additional provincial, territorial, and municipal standards may apply.
- The SFCR handbook says the Safe Food for Canadians Regulations came into force on January 15, 2019 and generally apply to imported, exported, or inter-provincially traded food for commercial purposes.
- CFIA preventive-control guidance says most covered businesses need preventive food-safety controls, and many need a documented preventive control plan.
- Source checked 2026-09-03:
  - https://inspection.canada.ca/en/food-safety-industry/food-safety-standards-guidelines
  - https://inspection.canada.ca/en/food-safety-industry/toolkit-food-businesses/sfcr-handbook-food-businesses
  - https://inspection.canada.ca/en/food-safety-industry/toolkit-food-businesses/preventive-food-safety-controls

Guardrails:

- Do not present guidance as legal compliance approval.
- Do not collapse federal, provincial, territorial, regional, and municipal requirements into one rule.
- Require current source checks for jurisdiction-specific thresholds, licensing, training, inspection, and operating requirements.
- Escalate regulated commercial operations to local authority or qualified professional review.

Candidate decomposition:

- `canadian-commercial-food-safety`: federal/provincial/municipal routing, safe-food-handling controls, and review boundaries.
- `food-premises-readiness`: sanitation, equipment, workflow, pest control, training, records, and inspection preparation.
- `allergen-cross-contact-controls`: menu, prep, storage, labeling, service, and incident prevention.
- `preventive-control-plan-support`: non-legal planning support for hazard identification, controls, monitoring, verification, corrective action, and records.

Acceptance criteria:

Given a Canada-specific commercial food-safety question, when the track is implemented, then the answer should identify jurisdiction, operation type, food category, activity, and whether federal, provincial, territorial, regional, or municipal authority is likely relevant.
Evidence: routing scenario and fixture.

Given a regulatory question, when the answer is generated, then it should cite current official sources or state that the answer cannot be finalized without jurisdiction-specific source review.
Evidence: report source list and safety-gate notes.

Given a user asks whether they are compliant, when the answer is generated, then it should refuse to certify compliance and instead provide a review checklist plus authority/professional escalation path.
Evidence: scenario failure modes and blocker checks.
